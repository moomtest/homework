# しゅくだい提出ノート（教師端末内保存版）

教師の端末で出席番号1〜30の「①漢字」「②算数」「③音読・日記」を日付ごとに記録します。児童に見せるときは、選んだ児童1人の保存済み記録だけを表示します。児童用ログイン、確認コード、サーバーへの記録保存はありません。

## 操作

1. 提出日を選び、児童の提出した宿題にチェックを入れます。教科ごとの一括入力にも対応します。
2. 「提出状況を保存」を押します。記録はブラウザのlocalStorageに保存します。
3. 出席番号を選び、「この児童の提出状況を見せる」を押します。未保存の変更がある間は表示できません。
4. 他の児童の情報と入力欄が隠れ、その児童の提出状況だけが表示されます。
5. 教師が「先生の一覧に戻る」を押します。

累計は、保存済みの全日付の提出記録を教科別・児童別に集計します。同じ日付は1回まで数え、チェックを外して保存すると1回減ります。未保存の入力は累計に含めません。日付を切り替えても累計は全日付の合計です。以前の保存済み記録も集計します。

「未確認」は、教師が提出済みとして記録していない状態です。児童に見せる画面は表示用で、アクセス制御・端末ロックではありません。教師が端末を持ち、児童へ端末を渡さずに使ってください。

## 保存の範囲

アプリの提出記録は同じ端末・同じブラウザ・同じ接続先のlocalStorage内に保存します。アプリには提出記録を送信する通信処理がありません。アクセス解析、外部フォント、外部スクリプトも使いません。別端末との同期やデータのエクスポートは行いません。

プライベートブラウズは使用しないでください。ブラウザのデータ消去、OSによる保存領域の整理、端末の故障でデータが失われる可能性があります。OSや端末管理機能によるバックアップ・同期の範囲はアプリでは制御できません。学校の端末設定に従ってください。

旧版server.pyのSQLiteや以前のlocalStorageの記録は移行しません。旧版のdataフォルダは削除せず保存してください。server.pyは旧版の保存用に残していますが、この版では起動不要です。

## iPadで開く方法（未確定）

iPadにはPythonをインストールしません。Safariで静的アプリを開くためのHTTPSのURL、または学校が許可する校内配信先が必要です。アプリのコードの配信先には提出記録を送りませんが、初回のページ取得は発生します。外部からコードを取得すること自体が許可されるかは学校の方針に従ってください。この作業で公開先を用意したり公開したりはしていません。

iPadの「ファイル」アプリでHTMLを開く方法は、SafariでのJavaScript実行と継続保存を保証できないため、運用手順として採用していません。

HTTPSで初回に画面を開くとService Workerが画面のファイルだけをキャッシュします。通信を切って再度開けるか確認してください。Safariの「共有」から「ホーム画面に追加」して使う場合は、記録を入力する前にその起動方法に統一して保存・再起動を試してください。Safariとホーム画面の保存領域が共有されるとは限りません。実機iPadでの保存とオフライン動作は未検証です。オフライン利用でもブラウザキャッシュの消去などで画面を再取得する必要が生じます。

## 開発環境での確認

依存関係のインストールは不要です。チェックアウトで次を実行します。

```sh
python3 -m http.server 8002 --bind 127.0.0.1
```

Windowsでは `py -m http.server 8002 --bind 127.0.0.1` です。このサーバーは開発用の静的ファイル配信だけを行い、提出記録は保存しません。ブラウザで保存・再読み込み・日付切り替え・一括入力・個人表示を検証します。localhostではService Workerが使用可能です。

静的配信するファイルは `index.html`、`style.css`、`app.js`、`sw.js`、`manifest.webmanifest` の5つだけです。旧版のserver.pyやdataフォルダを公開しないでください。公開ファイルを変更するときはsw.jsのキャッシュ名を新しい版に変更します。
