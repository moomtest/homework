# しゅくだい提出ノート（直接同期・端末内保存版）

教師の端末で出席番号1〜30の「①漢字」「②算数」「③音読・日記」を日付ごとに記録します。児童に見せるときは、選んだ児童1人の保存済み記録だけを表示します。外部サーバーへの記録保存はありません。本人確認して許可した児童のiPadへ、同じWi-Fi内の直接接続で本人の記録だけを送る試用機能があります。

## 操作

1. 提出日を選び、児童の提出した宿題にチェックを入れます。教科ごとの一括入力にも対応します。
2. 「提出状況を保存」を押します。記録はブラウザのlocalStorageに保存します。
3. 出席番号を選び、「この児童の提出状況を見せる」を押します。未保存の変更がある間は表示できません。
4. 他の児童の情報と入力欄が隠れ、その児童の提出状況だけが表示されます。
5. 教師が「先生の一覧に戻る」を押します。

累計は、保存済みの全日付の提出記録を教科別・児童別に集計します。同じ日付は1回まで数え、チェックを外して保存すると1回減ります。未保存の入力は累計に含めません。日付を切り替えても累計は全日付の合計です。以前の保存済み記録も集計します。

「未確認」は、教師が提出済みとして記録していない状態です。児童に見せる画面は表示用で、アクセス制御・端末ロックではありません。教師が端末を持ち、児童へ端末を渡さずに使ってください。

## 保存の範囲

アプリの提出記録は同じ端末・同じブラウザ・同じ接続先のlocalStorage内に保存します。通常のHTTP通信では提出記録を送信しません。アクセス解析、外部フォント、外部スクリプトも使いません。本人の記録は、教師が許可した直接接続先の児童iPadに送信・保存します。外部サーバーには記録を送信しません。カメラ画像も端末内でQRの読み取りにだけ使用します。

プライベートブラウズは使用しないでください。ブラウザのデータ消去、OSによる保存領域の整理、端末の故障でデータが失われる可能性があります。OSや端末管理機能によるバックアップ・同期の範囲はアプリでは制御できません。学校の端末設定に従ってください。

旧版server.pyのSQLiteや以前のlocalStorageの記録は移行しません。旧版のdataフォルダは削除せず保存してください。server.pyは旧版の保存用に残していますが、この版では起動不要です。

## iPadで開く方法

- 教師：https://moomtest.github.io/homework/
- 児童：https://moomtest.github.io/homework/student.html
- 古い画面が残る場合：https://moomtest.github.io/homework/update.html

iPadにはPythonをインストールしません。学校の許可のもとで、GitHub Pagesから静的なプログラムだけを取得します。提出記録は外部へ保存しません。初回はインターネット接続が必要です。Safariの通常タブを使ってください。

HTTPSで画面を開くとService Workerがプログラムとキャラクター画像をキャッシュします。教師用の保存・1人表示・オフライン表示はユーザーのiPadで確認済みです。新しい児童端末間の直接接続・カメラ読み取りは実機未検証です。

ホーム画面に追加する場合は、記録を入力する前に起動方法を統一して保存・再起動を試してください。Safariとホーム画面の保存領域が共有されるとは限りません。キャッシュの消去などで画面を再取得する必要が生じます。「ファイル」アプリのHTMLプレビューでの運用は想定していません。

## 開発環境での確認

依存関係のインストールは不要です。チェックアウトで次を実行します。

```sh
python3 -m http.server 8002 --bind 127.0.0.1
```

Windowsでは `py -m http.server 8002 --bind 127.0.0.1` です。このサーバーは開発用の静的ファイル配信だけを行い、提出記録は保存しません。ブラウザで保存・再読み込み・日付切り替え・一括入力・個人表示を検証します。localhostではService Workerが使用可能です。

静的配信するファイルは `.github/workflows/pages.yml` の許可リストに列挙したHTML・CSS・JavaScript・画像・QRライブラリとそのライセンスだけです。旧版のserver.pyやdataフォルダを公開しないでください。公開ファイルを変更するときはsw.jsのキャッシュ名を新しい版に変更します。

## がんばりトロフィー

児童1人の表示画面に、各教科6個（累計10/30/50回・連続10/30/50回）のトロフィーと称号を表示します。未達成はグレーのシルエット、達成済みは金色です。条件はマークの下に常時表示します。

保存された日付を昇順で並べて連続提出を計算し、その教科が未確認の記録で連続をリセットします。保存のない日付は飛ばすため、記録のない休日では連続が途切れません。全員・全教科が未確認で保存した日付も休日として飛ばし、連続回数を増やさず、連続をリセットしません。誰かの提出記録がある日は通常の提出日として児童・教科ごとに判定します。連続の判定には過去の最長連続回数を使い、後日の未確認で獲得済みトロフィーは消えません。過去の記録を訂正すると判定を再計算します。選択した表示日だけではなく全保存記録を対象とします。

## 教師による休みの設定

教師の一覧で提出日を選び「この日は宿題の提出が不要（休み）」をチェックして保存します。その日を累計・現在の連続・最長連続・トロフィー判定のすべてから除外し、連続をリセットしません。休みの日の提出入力は停止し、児童表示では「提出不要」と表示します。既存の提出チェックは削除せず保持し、休みを解除して保存すると再び集計します。過去の休みを設定・解除した場合も全記録から判定を再計算します。休み設定は提出記録と同じブラウザ内だけに保存し、旧データは設定なしとして読み込みます。全員・全教科未確認の日を連続記録から除外する従来のルールも継続します。

## 個別の提出不要（欠席など）

提出日を選び、その児童の行の「提出不要（欠席など）」をチェックして保存します。その児童のその日の3教科すべてを累計・連続回数・最長連続・トロフィー判定から除外し、連続を中断しません。他の児童は通常どおり判定します。個別提出不要の児童は一括入力の対象外です。元の提出チェックは保持し、提出不要を解除して保存すると元の記録が集計に戻ります。個人表示は「提出不要」と表示し、欠席などの理由は記録・表示しません。全員の休み設定と個別提出不要は独立して保存します。旧保存データは個別設定なしとして読み込みます。

## 更新が表示されないとき

インターネット接続中にアプリと同じ場所の `update.html` を開きます。未保存の入力を先に保存し、他のアプリのタブを閉じてから「保存を確認したので、最新版を開く」を押します。更新ページはオフラインキャッシュの対象外で、最新のService Workerを取得し、待機中の更新を明示的に有効にします。localStorageの提出記録は変更・削除しません。

## 児童に見せる画面

添付キャラクターをもとに整えたローカル画像を中心に、応援メッセージ、教科ごとの提出カード、トロフィーコレクションを表示します。画像もオフラインキャッシュ対象です。教師の一覧から児童を選んで表示し、他の児童の情報は隠します。


## 児童のiPadへの直接同期（試用）

### 保存・通信の条件

- 教師はこれまでどおり自分のiPadにクラスの記録を保存します。
- 児童は `student.html` をSafariの通常タブで開きます。本人の提出日ごとの記録、累計・連続・最長連続とトロフィー、教師の公開鍵、受信時刻だけを端末内に保存します。クラス全体の記録や他児童のデータ、欠席理由は送りません。
- 外部の記録保存先、シグナリングサーバー、STUN、TURN、アクセス解析は使用しません。静的ページとローカル同梱のQRライブラリをGitHub Pagesから取得しますが、記録をHTTPリクエストやURLに含めません。
- 同じWi-FiでWebRTC DataChannelが接続できる端末間のみ利用可能です。データチャネルはWebRTCのDTLSで暗号化されます。学校のWi-Fiの端末間隔離や端末管理設定で接続できない場合があります。
- 教師と児童の両方で画面を開き、本人確認して許可すると、接続中は教師が保存するたびに本人の記録だけを自動送信します。未保存の入力は送りません。
- アプリ終了・ロック・スリープ・通信断では更新が止まります。児童は最後に受信した記録を見られますが、未受信の更新は表示できません。画面に接続状態、最終受信時刻、教師の送信時刻を表示します。
- **再接続時はQR（または文字コード）の交換が必要です。** 外部のシグナリングサービスを使わないため、アプリを再び開いただけで再接続する機能はありません。
- 実機iPad・学校Wi-Fiでの接続、カメラでのQR読み取りは未検証です。まず架空の記録で2台を試してください。

### 接続手順

1. 教師は一覧の下の「児童のiPadと直接つなぐ（試用）」で対象の出席番号を選び、「接続コードを作る」を押します。
2. 児童は児童専用ページの「先生のiPadにつなぐ」を開き、「先生のQRをカメラで読む」で教師のQRを読み取ります。QRが複数なら「次のQR」で順番に読み取ります。カメラはこの操作時だけ使い、停止・画面を離れると終了します。文字コードの貼り付けでも交換できます。
3. 児童が「返信コードを作る」を押し、教師が「児童の返信QRをカメラで読む」で返信を読み取ります。
4. 教師が「返信コードを読み込む」を押します。
5. 教師が児童本人の端末であることと、両端末の確認番号が一致することを直接確認し、「接続を許可」を押します。それまで提出記録は送信されません。QRだけを一斉掲示したり、他の児童と共有したりしないでください。
6. 教師が保存すると、接続が続いている間は児童端末へ自動反映します。児童端末での保存完了が教師に通知されます。

### 本人限定の扱い

- 教師が選んだ出席番号を接続に固定します。児童の要求から出席番号を変更する処理や、クラス一覧の取得処理はありません。児童端末から教師の記録を変更する処理もありません。
- 教師の端末内でECDSA P-256の署名鍵を作り、送信する各記録に署名します。秘密鍵は教師端末から送りません。
- 児童は初回に受け取った教師の公開鍵と出席番号に登録を固定し、以後は違う児童・教師の記録、不正な署名、古い保存番号の記録を拒否します。
- これは学校アカウントによるログインではありません。最初の本人確認は教師が端末と確認番号を直接見て行います。別の児童や先生に切り替える場合は、教師の立ち会いで「このiPadの児童記録を削除」して登録し直します。
- 教師端末は教員専用とし、学校の端末ロックを使用してください。端末内データのOSバックアップや端末管理設定はアプリでは制御できません。児童端末も本人が使用する学校管理の端末を想定しています。

### 検証

```sh
node tests/peer-unit.cjs
PLAYWRIGHT_MODULE=/path/to/playwright TEST_ORIGIN=http://127.0.0.1:8010 node tests/sync-browser.cjs
PLAYWRIGHT_MODULE=/path/to/playwright TEST_ORIGIN=http://127.0.0.1:8010 node tests/qr-browser.cjs
```

ブラウザのテストには別途PlaywrightとChromiumが必要です。runtime依存関係はありません。開発用静的サーバーを対象ポートで起動します。通信レイヤーをメモリ上で代替したテストと、ブラウザの本物の署名検証・端末保存・画面表示を区別しています。開発環境はChromiumの管理設定 `WebRtcIPHandling=disable_non_proxied_udp` により直接接続の候補が得られないため、実WebRTCの端末間疎通は未検証です。設定を無効化せず、この制約を報告します。
